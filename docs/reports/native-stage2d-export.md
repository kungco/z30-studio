## 实际文件、改动及测试

photo_export_probe.rs 从固定 LibRaw DLL 读取公开 12/14 位 Z30 NEF，全尺寸九参数暖色显影后，在编码前释放原始线性帧与解码器，再调用实际 export::save 输出 JPEG/PNG/TIFF16。只在新建的绝对目录写入，已有目录拒绝；不覆盖原片。不是 1024 像素梯度代替实拍文件。tools/native_photo_export_benchmark.py 用独立 Pillow/tifffile 读取最终文件，对照保留的修正 Python float oracle，并核验 ICC、量化、重名保护、临时文件和原片 SHA。

export.rs 将纯 Rust JPEG 编码换为已静态接入的 MozJPEG，使用最快标准配置、4:4:4 和同一 JPEG 质量值，仍保留同目录临时文件/sync/最终不覆盖发布。ICC 使用符合规范的 **一基序号** APP2 标记；没有调用 mozjpeg 0.10.13 中从零编号的 ICC 辅助方法。编码/输出异常转为普通失败，新增失败 writer 和 JPEG 单边上限测试；已有 ICC/原片/发布保护不删减。

frame.rs 修正缩略图尺寸恰好为半整数时的舍入：与 Python round 一致采用 ties-to-even。独立 Pillow 参考增加 5×2→2×1 和转置场景，旧的 away-from-zero 会错出一列/行。52 个输入案例保持，缩放参考由 5 增至 7；未放宽数值阈值。

26 项 Rust 常规测试通过；另显式运行了真实 12/14 位全/半尺寸 RAW fixture，1 项通过（非默认 ignored 冒充已跑）。本阶段之前的原有 Python 163/Node 31 项通过，Python/前端产品代码未再改变。2C 的 eaa28c4 已通过 MSVC 原生和双 OS CI；本次提交需单独查 CI。

## 独立最终文件验证

优化前 native-full-nef-export.json 与优化后 native-full-nef-export-optimized.json 均保留，success=true。优化后两份样片：

- 尺寸均 3712×5568，源 12/14 位、相机白平衡、与前述暖色九参数相同；float 与修正 Python 最大误差分别约 6.01e-6 / 6.44e-6，原有门槛 2e-5 保持。
- TIFF 真实 RGB uint16/16 bits，均覆盖 65536 个不同码值，超过 6100 万个通道不是 8 位放大值；独立读取与实际渲染 float 的 16 位量化逐点一致。ICC 与内置 sRGB 字节一致。
- PNG 为 RGB8，独立读取与同一 float 的 8 位量化逐点一致，ICC 一致。
- JPEG 质量 95，独立解码对同一 RGB8 渲染结果 PSNR 分别约 37.69/38.22 dB，通过预设 35 dB sanity 门槛；这是有损输出，不能称逐像素一致或代替视觉评审。
- 两份 NEF SHA 全程不变；重复执行被拒，所有已有结果 SHA 不变，正常结束未留下 .part。没有原片覆盖开关。

## 单次耗时 / 内存

| 样片 | 解码 | 暖色显影 | TIFF16 编码 | PNG 编码 | JPEG 编码 | 原生峰值 |
|---|---|---|---|---|---|---|
| 12 位全尺寸 | 2.26 秒 | 8.36 秒 | .357 秒 | .414 秒 | .711 秒 | 479.2 MiB |
| 14 位全尺寸 | 2.22 秒 | 8.41 秒 | .364 秒 | .420 秒 | .696 秒 | 478.9 MiB |

旧原生 JPEG 编码实测约 33.99/31.05 秒，PSNR 37.65/38.18 dB；新路径更快且这两张的 PSNR 未下降。首次旧路径测量与查看器 smoke 有时间重叠，旧显影耗时约 14 秒不应用来推导显影提速；这里只把 JPEG 编码路径变化与文件质量明确列出。新显影约 8 秒仍慢于原始 Python 约 5.5 秒，不宣称 RAW 性能全面达标。每组仅一次，有频率/负载变化，未做稳定统计。
