# 阶段 5F1：受限局部形变的浮点核心

2026-10-27，基线 `6d0aa6f`（5E2b）。原 Python 基线未实现瘦脸/轮廓形变，本阶段新增独立核心和数值规范。**尚未接入桌面控件、配方保存或实际人脸轮廓定位，不能视为可用的一键瘦脸功能。**

`core/warp.rs` 提供最多四次有序小位移，坐标使用 `x*(w-1), y*(h-1)`，半径使用 `min(w,h)`。每次位移不超过半径的10%，整个作用圆必须处于照片内；不满足时拒绝处理。目标到来源的逆向采样与插值思想参考 [OpenCV 官方几何变换文档](https://docs.opencv.org/4.13.0/da/d54/group__imgproc__transform.html)，实现使用已有 Rust 类型，不增加运行库。

单次逆向场为 `f(q)=q-d·φ(q)`，目标中心 `t`、位移 `d=t-s`、半径 `R`；圆内 `φ=(1-|q-t|²/R²)²`，圆外为零。权重及一阶导数在边界归零；最大梯度 `8/(3√3R)`。位移限制使单场雅可比行列式至少约 `.846`，最多四次合成的下界约 `.512`。此约束保护几何方向，不保证真实五官/背景自然；作用圆内的背景仍可能被移动。

按逆序合成坐标后，直接在原始线性 RGB 做一次双线性重采样，使用同一组高精度权重处理三个通道，输出仍为 f32，保留负值和大于1的值。多个点不反复重采样图像。禁用/零位移返回 `None`，调用者直接引用原帧；启用时一份输出，原缓冲只读，不生成全尺寸 XY 坐标图。80MP帧、四控制点、联合包围框乘控制点不超过1.28亿映射步；输出分配可失败，处理前及每32行检查取消，取消的部分输出不返回。

`tools/generate_native_warp_reference.py` 使用独立 NumPy 向量化、解析雅可比和 float64 插值生成八组冻结参考，禁止覆盖。包含禁用、最大位移、斜向 HDR、左右对称、四点重叠、竖图纹理、恒定有符号/HDR和单像素宽图。`core/tests/warp_contract.rs` 核对全部像素及亚像素坐标、原帧不变、零分配禁用、区域外逐位相同、锚点/边界、四重最大位移的数值雅可比、非法/超预算输入与中途取消。期望值不从 Rust 输出产生；原十组修复参考与所有旧容差保留。

验收：Rust **110**、两项显式 RAW/CPU 人脸 fixture、完整 Python **180（含 RAW、无跳过）**、Node **31** 通过。Release 探针八组像素与冻结参考的最大误差 **0**，坐标最大误差约 **3.55e-15**；固定允许值分别为2e-6与1e-9。旧修复十组仍通过，最大4.768e-7。`-WarpProbe` 构建仅供开发使用的 `warp_probe` / `warp_benchmark`，没有给产品添加隐蔽开关。

约2000万像素生成线性图三轮CPU观测：禁用中位约 **.010秒 / 232MiB峰值**，一控制点约 **.036秒 / 460MiB**，四点约 **.058秒 / 460MiB**。多约228MiB为一份浮点输出。计时不含生成输入或验证输出，峰值为整个进程；这些不是实际 NEF 人像、模型推理或整条显影性能。双线性插值可能柔化纹理，尚未验证真实细节、缩略图/最终图的主观一致性或抗混叠质量。

既有显影配方与界面不调用本核心，草稿v6/队列v4保持。最终干净包将对既有289项真实进程流程、五份默认及两份既有非零修复 RAW TIFF、对应CI复验；提交/包哈希和性能对照以本机 checkpoint/final-artifact为准。5E2b 的实际鼠标修复仍可用，新的形变核心尚无产品操作入口。

后续需接原片绑定、保存/撤销、源空间局部处理与形变顺序、蒙版/标记坐标转换和完整导出，单独验收。当前五点面部定位没有下颌轮廓；更密的关键点方案可另评估 [Google Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker)，其模型、许可和运行时尚未安装或验证。自动瑕疵识别、真实Z30人像/各种肤色、自然轮廓、干净Windows/高DPI、GPU和完整高级功能仍待。没有付费调用、模型下载、原片改写、CLI登录变化、自动续跑或关机；历史Python退出超时根因仍未闭环。
