# P0 可靠性与数据安全（2026-10-24）

基线为 3d68fdd；本阶段源码 1.4.0。Windows 包将在完整 P0/P1/P2 清单结束后重建，旧 1.3.0 包不能当作本阶段功能。用户要求全部完成后正常关机；本阶段完成不触发关机。

## 实现

- `shutdown_watchdog.py` / `desktop.py` / `server.py`：独立 Windows 子进程在启动时固定父进程句柄；原生停止事件及诊断停止文件都能独立触发。阶段超时默认 8 秒，总预算 20 秒；超时仅终止自己的父进程，记录停止观测与最后阶段。父进程卡在 GIL/原生调用、未产生日志时仍可限时退出。阶段 JSON 原子替换；日志磁盘满不关闭看门狗。源码 `server.py` 直接运行没有独立进程监护，应通过 `desktop.py` / EXE 使用此功能。
- `export_jobs.py`：关停的 5 秒预算覆盖锁等待和清单保存；快照复制/哈希移出队列与会话锁；快照和结果先 fsync、后原子发布，迟到结果不发布。启动清理 `.part`/临时清单，复核原片哈希和新结果哈希，丢失结果转可重试、损坏原片显示错误。已有成功项保留，不自动重跑模型或导出。
- `diagnostics.py` / 顶部“导出诊断”：只包含白名单日志和最近阶段记录，限制单文件大小，替换明显的密钥格式；不含原片、草稿、模型配置、Codex 身份。堆栈可能含本机路径，用户决定如何分享。
- `drafts.py` / `web/draft-save.js`：SQLite FULL 同步事务 + fsync 的不可变去重原片；短间隔自动保存、分钟版本、手动快照和回滚，保留 20 个历史版本。操作 ID 幂等，版本比较拒绝旧页面覆盖；失败不更新已确认的版本。启动列出草稿，关闭浏览器或崩溃后可以恢复。最新尚未收到保存成功确认的操作不能保证恢复。
- `projects.py` / `server.py` / `web/app.js`：便携项目和工作区 256 张 / 8 GiB；单张仍为 150 MiB，空闲租期 24 小时，活跃页面每 30 秒续期。导出每批 256 张 / 8 GiB，任务快照+结果预算 20 GiB；草稿原片另有 20 GiB 预算。大草稿/会话恢复使用缩略图及按选中照片加载，缓存继续保持 128 MiB；便携项目仍包含原片，不是引用外部路径的项目格式。

## 验证

- 本阶段全量 **116 Python 方法、28 Node 测试通过**；保留最初 11 项 CLI 契约测试，包含外部 CC0 12/14 位 NEF。未调用付费 API。
- 新增检查：SQLite 事务中直接 os._exit 的崩溃回滚；原片去重/存储限额/缺失校验；保存响应丢失的幂等重试、并发版本冲突；256 照片便携项目往返；100 照片草稿恢复不解码整个图库；关闭会话不删除持久原片；HTTP 保存/恢复/历史/冲突；诊断白名单。
- 看门狗故障注入让父进程完全不处理停止信号：独立观察后在阶段期限结束父进程（退出码 3），写出最后阶段。正常退出和故障注入连续三组通过。测试发现并修正了新增握手文件的 Windows 共享句柄删除竞争，采用原子发布并保留 ack；这不是早期偶发 30 秒等待的原始根因结论。
- 浏览器实测：真实 14 位 NEF，自动保存后选择暖调胶片；强制结束专用测试服务进程，重启，启动恢复面板找回草稿、原片与两步历史，参数与预设一致。截图位于 outputs/Z30-Studio-P0-recovery.png（发布包不包含原片）。
- smoke 的异常路径现在也落盘 `shutdowns` 和失败类型，同时保存独立看门狗日志；最终发布时再验证实际 EXE。

## 残余风险

- 早期偶发 30 秒等待原始根因仍未证实。现在验证的是独立限时兜底与可诊断行为，不把“重跑通过”当作根因修复。看门狗超时可能终止未完成的单张编码，已确认草稿及已发布结果保留。
- 极端断电/物理磁盘故障不能等同于进程崩溃；SQLite/文件原子写入不能替代异地备份。草稿不是原片的唯一备份，建议另存 `.z30proj`。
- 256 张验证使用生成夹具；100 张惰性恢复用小图。没有 256 张真实 NEF、8 GiB 实际便携包、慢网络盘、低空间真实磁盘或干净虚拟机验证。大便携包打开需要足够的上传/解包/临时副本空间。
- P1/P2 清单仍待完成；真实 DeepSeek 推理未验证，没有因自动保存或恢复发起模型调用。
