# 阶段 4A：持久批量队列核心

日期：2026-10-26。阶段 4 尚未完成，此报告仅覆盖队列核心，不代表桌面批量界面已可用。

修改 `native/crates/core/src/batch.rs`、`export.rs`、`lib.rs`：批量加入任务时固定每张照片的配方、原片绝对路径、大小及修改时间，并给每个目标生成稳定的独立文件名。最多保留 512 个任务；加入一批时先检查所有照片与输出冲突，再整体写入队列。每个任务必须先以 `running` 状态落盘，再调用现有单张全尺寸导出；导出仍使用同目录临时文件与无覆盖发布。队列文件使用单实例锁、大小限制、校验及磁盘版本比较，读取失败时禁止写回。

进程重启时，运行中的任务转为 `interrupted`；所有未完成任务保持暂停。目标文件可能已在崩溃前发布，因此重试会跳过已有目标，绝不将它覆盖或冒充成功。失败、取消和中断任务可显式重试；暂停在任务边界生效。原片发生变化会拒绝导出。

验证：Rust workspace 测试 50 项通过、1 项公开 RAW fixture 测试按设计跳过；Debug 原生程序构建成功。新增测试实际导出两张配方不同的 TIFF16、比较结果并确认原片字节未变；还测试运行中断、已有目标拒绝覆盖、原片变化、坏队列保留原文件。未在本阶段验证真实 Z30 NEF 批量输出、桌面交互或干净 Windows。

剩余风险：源指纹使用文件大小和修改时间，不是完整内容哈希；极端情况下文件内容被改写且刻意保留这两项信息，队列不能识别。崩溃时编码中的临时 `.part` 可能留在输出目录，后续需加入有界清理/恢复提示。批量任务目前顺序执行，缓存与峰值内存改进仍待阶段 4 后续工作。
