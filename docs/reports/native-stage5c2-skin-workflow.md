# 阶段 5C2：皮肤区域接入桌面、草稿与导出

2026-10-27；基线 `aa00122`。本报告与 JSON 记录提交前源码验证，干净提交、ZIP 解压复测及对应 GitHub CI 另见 `.development/checkpoint.json`。仍是原生迁移开发预览，完整阶段 5 和高级暗房迁移尚未完成。

## 用户能使用的行为

显影面板下部“本机人像”：定位面部后点击“识别皮肤”，检查绿色实际作用区域，再调整柔化强度。新识别不会自动增加强度。语义皮肤、面部几何边界和眼嘴保护共同限制柔化；绿色层只是窗口提示，不写入导出图像，查看调整前时隐藏。放大、适合窗口和定位框使用相同几何变换。

皮肤区域随草稿保存，可撤销/重做、重启恢复，预览、单张与持久批量任务使用同一配方。已保存区域的恢复和显影无需推理模型或 ONNX DLL；RAW 原片解码仍需 LibRaw。公共批量同步只同步全局参数和白平衡，每张照片保留自己的蒙版与面部位置。

未知/损坏模型、原片变化、参数/选片变化和取消会阻止旧结果应用；空区域或选中面部不足八个可信模型像素时保留原配方，不扩大到几何区域。新识别仍需可选 CPU 组件及系统 Microsoft VC++ x64；没有自动下载、云端推理、收费接口或 CLI 登录方式变更。

## 实际修改文件

- `native/crates/core/src/skin.rs`：不可变共享蒙版、原片绑定、SHA-256 校验、无损 `rle8` 和不可压缩时 `raw8`；严格限制编码/展开长度与版本。摘要覆盖绑定和原始蒙版像素，格式变化不改变像素。
- `recipe.rs`、`editing.rs`、`rendering.rs`：配方由 Copy 改为共享数据的 Clone；识别结果作为一步撤销，全局/AI 调整保留蒙版。默认显影使用保存蒙版，显式传空值也不会丢掉它；冲突的外部蒙版被拒绝。撤销、工作线程和导出快照共享 64 KiB 数据，不逐步复制。
- `session.rs`、`batch.rs`、`bounded.rs`：草稿写 v4/读 v1–4，队列写 v2/读 v1–2；迁移前保留旧 JSON 原字节备份。保留独占锁、CAS、临时文件/同步/原子发布和损坏保护。草稿 256 张/32 MiB，队列 512 任务/64 MiB；反序列化时即限制数组数量，不能只提高字节上限后任意分配记录。
- `native/crates/desktop/src/skin_workflow.rs`、`main.rs`、`qa.rs`、`ui/main.slint`：本机模型选择、后台识别、实际区域叠加、照片/参数/原片过期保护、共享取消与关闭流程；只缓存一个叠加图，使用蒙版摘要和人脸作为缓存键。每次显式识别均校验模型和运行库，任务后释放模型会话。
- `tools/prepare_native_skin.py`、`package_native.py`、`native_build.ps1`、`native/vendor/skin/manifest.json`：独立 `skin/` 可选组件和 `-SkinRuntime` 构建参数；要求已有审计过的 `vision/` 运行库，检查四文件、固定摘要与许可，拒绝覆盖、未声明组件和依赖缺失。RAW 随包要求保留。
- `native/crates/core/tests/skin_contract.rs`、`examples/skin_persistence_probe.rs`、`tests/test_native_skin_assets.py`、`tools/smoke_native_skin.py`：实际存储、像素、来源和生命周期回归及容量基准。
- `Cargo.toml/lock`、原有编辑/AI/预览探针与测试的少量改动：复用桌面已有 base64 0.23，适配非 Copy 配方。原断言的数值容差未放宽；旧版迁移断言升级到 v4，并新增 v3 原字节备份回归。原 Python 实现保留。

## 容量、耗时与内存

同一公开图生成的蒙版，Base64 载荷从 87,384 字节降至 **908 字节**，解压像素逐字节一致。无损压缩是减少草稿/队列重写量；它不减少图像位深，也不是调色质量变化。

以下是实际皮肤蒙版/最坏噪声蒙版配合**占位原片记录**的独立 Release 存储基准，不是 256 张真实照片解码或多人像画质测试：

| 256 张 / 512 任务 | 草稿字节 | 队列字节 | 草稿存/读 | 队列存/读 | 进程峰值 |
|---|---:|---:|---:|---:|---:|
| 本次皮肤区域 | 1,051,677 | 2,273,482 | 15 / 14 ms | 20 / 29 ms | 61.6 MiB |
| 不可压缩蒙版 | 23,188,875 | 46,546,854 | 46 / 31 ms | 96 / 62 ms | 194.1 MiB |

均完整保存/恢复。该峰值属于存储探针，不能和全尺寸 NEF 处理内存直接相加或当作窗口驻留值。数值是同机单次观测，文件系统/系统负载会影响结果。公共 PNG 的实际窗口识别、内存和关闭观测见附带 JSON；不是实机 Z30 人像性能结论。

## 使用与复跑

带组件构建同时提供 `-RawRuntime`、`-VisionRuntime` 和 `-SkinRuntime`。完整解压后保留 `raw/`、`vision/`、`skin/` 和许可文件；基础包可不带两个模型，仍可恢复已有 PNG 人像编辑。新皮肤组件必须用当前 `prepare_native_skin.py` 准备，旧 5C1 组件的声明文件不会被覆盖。

```powershell
./tools/native_build.ps1 -ToolchainRoot D:/codex/toolchains/z30-native -Test -SkinProbe -SkinPersistenceProbe -RawRuntime RAW_COMPONENT -VisionRuntime VISION_COMPONENT -SkinRuntime SKIN_COMPONENT
python tools/smoke_native_skin.py --exe ABS_Z30Studio.exe --assets VISION_COMPONENT --skin SKIN_COMPONENT --image PUBLIC_ASTRONAUT.png --bundled --out NEW_REPORT.json
```

## 残余风险与下一阶段

1. 只验证有限公开图与合成数据，用户 Z30 人像、多肤色、眼镜/遮挡/极端光线未验收。5C1 中实体倒置 180° 返回空皮肤门控，三种实体旋转未检出可用 YuNet 人脸；远处小脸可能安全拒绝。256×256 模型不是精细皮肤/发丝选择。
2. 仍按路径摘要/大小/时间/尺寸绑定；同路径同长度且刻意保留时间戳的内容替换仍无法检测。移动原片需要重新绑定；完整项目重定位工作流待阶段 6。
3. 损坏蒙版使草稿整体只读保护，尚无原生逐张修复向导；旧文件保留，可从迁移备份恢复。恢复已有蒙版不等于支持无原片导出。
4. 干净 Windows、高 DPI、GPU、真实云端和全尺寸 Z30 人像肤质仍未验证；CPU 运行库依赖系统 VC++ x64。未重新定位此前偶发退出超时的全部根因，只记录当前识别/关闭流程通过。
5. 瑕疵修复、均匀肤色、轮廓形变、GPU 及原有完整高级暗房/项目/局部蒙版迁移仍待后续阶段。没有合并 main 或发布正式版。
